# ERP-система управления зоопарком

## Описание системы

Система автоматизирует управление зоопарком и моделирует:
- **Животных** различных видов (млекопитающие, птицы, рептилии) с их способностями (бег, полёт, плавание)
- **Персонал** (смотрители, ветеринары) и их обязанности
- **Процессы ухода** за животными (кормление, медосмотры, уборка)
- **Вольеры** для размещения животных
- **Отчётность** по животным, графикам кормления и медицинским данным

---

## Применение принципов SOLID

### 1. SRP

Каждый класс имеет одну ответственность:

- `Zoo` — хранение ресурсов (животные, сотрудники, вольеры)
- `FeedingService` — управление кормлением
- `MedicalService` — медицинское обслуживание
- `ReportingService` — генерация отчётов
- `Keeper` — физическая работа (кормление, уборка)
- `Veterinarian` — проведение медосмотров

---

### 2. OCP

Система открыта для расширения, закрыта для модификации:

- Добавление новых животных с использованием текущих интерфейсов Runnable, Swimmable и тд;
- Добавление новых сотрудников: охранников, менеджеров.

---

### 3. LSP

Подклассы корректно заменяют базовые классы:
```java
Animal simba = new Lion("Симба", 5, 190.0, "Золотистый", 12, 3);
Animal dumbo = new Elephant("Дамбо", 8, 5000.0, "Серый", 15, 2);
Animal rio = new Parrot("Рио", 3, 1.2, 0.5, "Разноцветный", 0.5, 2);
Animal petya = new Snake("Петя", 6, 5, "Ребристая", 2, 1);

zoo.addAnimal(simba);
zoo.addAnimal(dumbo);
zoo.addAnimal(rio);
zoo.addAnimal(petya);

mammalEnclosure.addAnimal(simba);
mammalEnclosure.addAnimal(dumbo);
aviaryEnclosure.addAnimal(rio);
terrarium.addAnimal(petya);

```
Однако в таком случае нельзя будет использовать методы поведения животных, например
```java
simba.run();
rio.fly();
```
и придется делать проверку на instanceof и кастовать к соответствующему интерфейсу
```java
if (simba instanceof Runnable) {
    ((Runnable) simba).run();
}
```

---

### 4. Interface Segregation Principle (ISP)

Интерфейсы разделены — каждое животное реализует только необходимые.

**Интерфейсы ухода:** `Feedable`, `Treatable`, `Cleanable`

**Интерфейсы способностей:** `Runner`, `Flyable`, `Swimmable`

Реализация:
```java
class Lion implements Feedable, Treatable, Cleanable, Runner { }
class Parrot implements Feedable, Treatable, Cleanable, Flyable { }
class Snake implements Feedable, Treatable, Cleanable, Swimmable { }
```

Преимущество: попугай не обязан реализовывать `run()`, лев — `fly()`.

---

### 5. Dependency Inversion Principle (DIP)

Модули зависят от абстракций, а не от конкретных реализаций:
```java
public class FeedingService {
    public void createFeedingSchedule(Animal animal) {
        if (!(animal instanceof Feedable)) return;
        Feedable feedable = (Feedable) animal;
    }
}
```

Сервисы работают с интерфейсами (`Feedable`, `Treatable`), не зная про конкретные классы (`Lion`, `Parrot`).

## Проблемы при расширении функционала

### 1. Координация большого количества сотрудников и операций
**Проблема:** При увеличении числа сотрудников и разными операциями(кормление уборка и тд) Main становится перегруженным. Нужно всем вручную управлять.  
**Решение:** Ввести классы управления сотрудниками и операциями для автоматического распределения задач между сотрудниками и управления операциями(главное избежать Service Locator).

### 2. Отсутствие валидации
**Проблема:** Нет проверки корректности данных в конструкторах (возраст < 0, вес < 0, пустое имя).
**Решение:** Это недостаток текущего кода, который достаточно легко исправляется условиями.

### 3. Работа программы в режиме реального времени
**Проблема:** В идеале программа должна работать в режиме реального времени для выполнения разных операций(кормления, медосмотров).
**Решение:** Добавление логики сравнения расписания с текущим временем и статусов выполненных операций(выолнено, в процессе).

---

## Аргументы за введённые абстракции

### 1. Разделение интерфейсов (Feedable, Treatable, Runner, Flyable, Swimmable), что способствует удобному добавлению новых животных.

### 2. Выделение сервисов (FeedingService, MedicalService, ReportingService). Логика отделена от данных, что позволяет проводить независимое тестирование.

### 3. Зависимость от абстракций: новые животные автоматически поддерживаются сервисами, что позволяет тестироваться на mock-объектах
